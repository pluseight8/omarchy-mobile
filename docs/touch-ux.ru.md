# Спецификация сенсорного интерфейса

Это поэтапная спецификация. Прототип реализует только поведение со статусом «есть сейчас». Остальное — целевое поведение; его нельзя представлять как работающую функцию.

## Есть сейчас

| Действие | Поведение прототипа |
| --- | --- |
| Нажатие на карточку | Запуск через scoped application-library facade Omarchy |
| Прокрутка списка | Flickable GridView |
| Долгое нажатие на карточку | Панель с деталями приложения и кнопкой запуска |
| Поиск | Фильтрация через ту же библиотеку приложений upstream |
| Закрытие | Кнопка на экране; Escape при фокусе поля поиска |
| Размер элемента | Минимальная сенсорная область рассчитывается через Style.space(48) |

Число колонок сетки рассчитывается по текущей логической ширине. Физическое разрешение Pixel не используется как размер QML-окна.

## Целевое поведение, которое ещё не реализовано

- Свайп вверх для главного экрана, свайп с удержанием для обзора, горизонтальный свайп рабочих пространств, возврат от края и верхняя системная панель.
- Правила арбитража, если содержимое приложения также использует край экрана или горизонтальные жесты.
- Мобильная модель рабочих пространств с повторным использованием Hyprland и управления окнами Omarchy.
- Интеграция показа/скрытия клавиатуры по Wayland input-method и text-input протоколам, поддерживаемым выбранным композитором.
- Учёт клавиатуры при изменении окна или отступов, чтобы поле ввода оставалось видимым.
- Безопасные области, вырез дисплея, поворот, преобразование сенсорных координат и масштабирование.
- Центр уведомлений, системные панели, clipboard, медиауправление, экран блокировки и питание.
- Переходы при подключении внешнего дисплея, физической клавиатуры и мыши.

## Проверки до объявления мобильной готовности

1. Запустить закреплённые Omarchy и Quickshell-плагин в ARM64 Linux-сеансе.
2. Проверить нажатия, долгое нажатие, прокрутку, поиск, фокус, закрытие и запуск сенсорным вводом.
3. Проверить портретную и альбомную ориентацию с несколькими масштабами композитора, длинными строками и открытой виртуальной клавиатурой.
4. Записать снимки экрана и сенсорные трассы; проверить, что элементы не выходят за границы вывода.
5. Проверить конфликты жестов на нескольких приложениях и задокументировать правила выбранного композитора.
6. Повторить важные проверки на Pixel 10 только после отдельной готовности дисплея и ввода.

Для этого репозитория пока нет снимков интерфейса или испытаний сенсорного ввода на устройстве.
