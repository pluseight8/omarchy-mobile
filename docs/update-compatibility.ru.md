# Совместимость с обновлениями upstream

Исходники Omarchy меняются. Совместимость измеряется для конкретных commit Omarchy, набора пакетов и ревизии мобильной адаптации; она не обещает совместимость с будущими версиями.

## Записанная версия

compatibility.json содержит проверенный commit исходников Omarchy, commit репозитория пакетов, исходную ревизию из PKGBUILD, версию мобильной адаптации и фактически выполненные категории проверок. Сейчас указано STATIC_SOURCE_REVIEW_ONLY. Это не испытанная runtime-комбинация.

## Workflow мониторинга

Плановый GitHub Actions workflow получает полную историю актуальных quattro и omarchy-pkgs master, находит последний официальный релиз Omarchy и запускает контрактные тесты для ветки и релиза. Он сравнивает выбранные API плагинов, host, theme, menu, overlay и рецепты пакетов с проверенными ревизиями и формирует отчёт. Изменения контролируемых файлов создают одну deduplicated issue для проверки. Сборки пакетов пока нет.

Это обнаружение изменений. Оно не решает, что изменение ломающее, не обновляет pin, не собирает ARM64-пакет, не запускает Quickshell, не проверяет миграции, не выпускает релиз и не обновляет телефон. Нужно вручную изучить diff и запустить отсутствующие проверки.

## Условия выпуска

Перед маркировкой кандидата как совместимого записать:

- Тег Omarchy и точный исходный commit.
- Commit omarchy-pkgs и точные исходные ревизии пакетов.
- Commit мобильной адаптации.
- Результат ARM64-сборки и контрольные суммы пакетов.
- Результаты проверок manifest плагинов, IPC, тем, компонентов и CLI.
- Результат запуска Quickshell и доказательства визуального взаимодействия.
- Результат проверки миграций и здоровья после обновления.
- Известные регрессии и статус проверки устройства.

Если какая-либо проверка не выполнялась, сохранить pin релиза и обозначить кандидата как непроверенного. Обновления безопасности всё равно следует разбирать оперативно; фиксация версии не означает игнорирование изменений безопасности.

## Граница обновления и восстановления

Обычные обновления должны использовать штатные команду Omarchy, pacman/ALPM, hooks и миграции. Мобильный адаптер может добавить предварительную проверку совместимости и последующий health check после определения цикла пакетов. Перед миграциями нужна резервная копия пользовательской конфигурации. Rollback можно обещать только после совместной проверки кэша пакетов, восстановления состояния и пути загрузки.

Ядро, firmware, загрузчик, verified boot и разделы относятся к отдельному обслуживанию устройства. Такие операции не входят в плагин и не реализованы в этом репозитории.
