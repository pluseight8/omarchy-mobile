# Сборка и среда разработки

Дата состояния: 2026-10-12.

## Что доступно сейчас

Текущий прототип не содержит собранного пакета. Локальные проверки используют встроенный тестовый runner Node и не требуют внешних npm-зависимостей:

    npm test

Для сравнения с живыми исходниками нужна локальная копия omacom/omarchy с полной историей:

    OMARCHY_UPSTREAM=/path/to/omarchy node tools/check-upstream.mjs

GitHub workflow настроен на QML syntax lint и проверки исходников на публичном ARM64 runner с меткой ubuntu-24.04-arm. GitHub Actions закреплены по commit SHA. Образ runner, версии пакетов Qt/Node и ветки upstream обновляются, поэтому это пока не побитово воспроизводимая сборка системы. Workflow ещё не запускался для этой ветки.

## Чего пока нет

Нет закреплённого Arch Linux ARM rootfs, контейнера сборки, репозитория пакетов, сборщика образов, initramfs, ядра frankel или загружаемого системного образа. Общий AArch64-образ Arch Linux ARM — отправная точка для будущей работы, но не способ установки на Pixel 10. Чтобы называть среду воспроизводимой, rootfs нужно закрепить по неизменяемой ревизии источника и проверить контрольную сумму.

Следующая задача build-системы — определить сборщик AArch64-пользовательского окружения с закреплённой версией, способный запускать makepkg для реального набора upstream-пакетов. Нужно использовать PKGBUILD upstream и сохранять условия для разных архитектур. Сначала CI должен собрать небольшой набор пакетов и сохранить их контрольные суммы и исходные ревизии; firmware без проверенного происхождения или лицензии включать нельзя.

## Требования к runtime-тесту Quickshell

До заявления о работоспособности launcher необходимо запустить его в сеансе Omarchy, собранном из записанного upstream commit. Проверить обнаружение manifest, жизненный цикл открытия/закрытия, API библиотеки приложений, импорты QML, иконки, сенсорную прокрутку, долгое нажатие, поиск и запуск приложений. Зафиксировать композитор, Qt, Quickshell, масштаб, ориентацию и снимки экрана. Текущий CI этого не делает.

## Безопасность образов и устройства

Здесь образ не собирается. Нельзя использовать стандартный ISO Omarchy как образ смартфона. Любой будущий образ Pixel должен иметь маркировку experimental и untested до испытаний на реальном устройстве. Не блокируйте загрузчик, не меняйте метаданные verified boot и не публикуйте инструкцию прошивки, пока не появятся проверенный процесс восстановления, точные входные данные сборки и отчёт испытания устройства.
