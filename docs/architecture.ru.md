# Архитектура и текущее состояние реализации

Дата аудита: 2026-10-12. Здесь описан первый прототип репозитория, а не законченная мобильная ОС.

## Граница системы

Omarchy остаётся владельцем пользовательского сеанса: хоста оболочки, Quickshell, конфигурации Hyprland, CLI, тем, реестра плагинов, IPC, обновлений, миграций и настроек. Этот проект добавляет один необязательный сторонний плагин меню. Он использует уже предоставляемый меню-плагинам API библиотеки приложений и публичные компоненты интерфейса Omarchy для тематических оверлеев.

Launcher не форкает каталог приложений upstream, не устанавливает приложения, не управляет окнами, не владеет системным жестом домашнего экрана и не вводит новую систему обновлений. После запуска приложения он закрывается и поручает запуск существующей библиотеке Omarchy.

## Слои

| Слой | Ответственность | Состояние в репозитории |
| --- | --- | --- |
| A. Upstream Omarchy | Runtime, хост Quickshell, плагины, темы, CLI, службы, IPC, пакетный цикл и обновления | Используется интерфейс стороннего плагина меню; исходные файлы не копировались |
| B. Мобильный интерфейс | Сетка приложений с крупными сенсорными элементами, поиск, запуск нажатием, детали при долгом нажатии, адаптивное число колонок | Код прототипа mobile/launcher/Launcher.qml; runtime не проверен |
| C. Интеграция платформы | ARM64-пакеты, мобильный ввод, питание, ориентация, уведомления и интеграция сеанса | Только исследование; служб и пакетов пока нет |
| D. Поддержка устройства frankel | Ядро, DT, загрузка, firmware, восстановление и проверка | Только внешние экспериментальные источники; кода устройства и образа нет |

## Контракт плагина

Manifest использует schema version 1, вид menu и QML-точку входа Item. Хост Omarchy передаёт shell, manifest и методы жизненного цикла. Плагин меню получает ограниченный API библиотеки приложений через shell.appLibrary. Launcher вызывает upstream-методы sortedEntries, entryName, entrySubtext, iconSource, refreshIcons и launch.

Интерфейс использует PanelWindow/WlrLayershell из Quickshell вместе с qs.Ui.BorderSurface, qs.Commons.Style, qs.Commons.Border и qs.Commons.Color. Это сохраняет совместимость с текущим релизом v4.0.4: встроенное меню использует PanelWindow, а более новый wrapper qs.Ui.OverlayWindow в этом релизе отсутствует. Владение темами остаётся в upstream. Как и остальные сторонние плагины Omarchy, этот плагин выполняется в процессе оболочки без песочницы.

Контракт документирован upstream в проверенном commit: https://github.com/omacom/omarchy/blob/4c1b4cb3a94447aff39af98e2fcc0490a9fb32e7/docs/omarchy-shell.md. Точные пути к исходникам и ревизии приведены в отчёте об исследовании.

## Сенсорное поведение прототипа

- Приложения расположены в сетке; число колонок зависит от доступной логической ширины.
- GridView обеспечивает прокрутку на базе Flickable.
- Нажатие запускает приложение через upstream-библиотеку.
- Долгое нажатие открывает панель с деталями и кнопкой запуска.
- Поиск фильтрует тот же каталог приложений.
- Кнопка закрытия и Escape скрывают меню.
- Минимальный размер интерактивного элемента рассчитывается через Style.space(48).

Пока не реализованы: системные жесты домашнего экрана и списка приложений, свайп между рабочими пространствами, возврат от края, арбитраж конфликтующих жестов, безопасные отступы, ориентация от датчиков, вызов экранной клавиатуры, мобильные уведомления, экран блокировки, системная панель и адаптация рабочих пространств к нескольким окнам. Подсказки input-method для текстового поля не доказывают поддержку со стороны композитора или клавиатуры.

## ARM64 и обновления

В проверенных исходниках Omarchy и omarchy-pkgs есть поддержка ARM64, включая рецепт Quickshell для aarch64. Это основание изучать пакетирование, но не доказательство успешной ARM-сборки Omarchy Mobile. В репозитории пока нет пакета, root filesystem, ядра, initramfs или воспроизводимого образа релиза.

compatibility.json закрепляет проверенный commit и явно перечисляет непроведённые проверки. Плановый workflow отслеживает выбранные файлы контрактов upstream и создаёт одну issue для проверки, если они меняются. Статические тесты контракта не являются сертификатом совместимости. Перед выпуском нужно закрепить явный commit upstream и пройти runtime-, пакетные и миграционные проверки.

Команда обновления Omarchy, pacman/ALPM, пользовательские настройки, post-update hooks и миграции остаются ответственностью upstream. Мобильный слой должен добавить предварительные и health-проверки через небольшой адаптер после выбора поддерживаемого цикла пакетов. Обновление ядра, firmware, загрузчика или таблицы разделов нельзя смешивать с обычным обновлением пакетов Omarchy.

## Критерии этапов

| Этап | Минимальное доказательство |
| --- | --- |
| Исследование | Датированный аудит первоисточников; неизвестное оборудование остаётся неизвестным |
| Основа ARM64 | Воспроизводимый rootfs с закреплённой версией и сборка пакетов на ARM64 runner |
| Прототип Quickshell | Плагин загружается в закреплённой оболочке Omarchy; собраны ошибки QML; записано взаимодействие в вертикальной и горизонтальной ориентации |
| Сенсорная адаптация | Проверены ввод, прокрутка, долгое нажатие, клавиатура, фокус и конфликты жестов на совместимом композиторе |
| Bring-up frankel | Документирована serial-загрузка, версии ядра/DT, восстановление и проверки компонентов на Pixel 10 |
| Повседневное использование | Реальные испытания связи, экстренных вызовов, зарядки, сна/пробуждения, безопасности, обновлений и восстановления |

После этапа исследования ни один следующий этап не завершён.
