# Device manifests

[English version](README.md)

Каждое устройство описывается JSON manifest. Manifest фиксирует, что реализовано, что только запланировано и что реально проверено. Он намеренно отделён от Omarchy shell, чтобы добавление устройства не создавало вторую реализацию desktop-среды.

Словарь статусов намеренно консервативен:

- `planned` означает, что предусмотрена точка интеграции, но нельзя считать реализацию или доказательства существующими.
- `untested` означает, что code или device contract может существовать, но разработчик не проверял устройство на реальном железе.
- `experimental` означает, что эксперимент на реальном устройстве может быть возможен, но это не обещание поддержки.
- `validated` разрешён только для воспроизводимого отчёта, который покрывает необходимое hardware, boot, recovery, power и data-safety тестирование.

`realHardwareValidated` должен оставаться `false`, пока не существует validation report. Зелёный CI проверяет только repository contracts и не может повысить статус устройства.

Pixel 10 — reference starting point. Его manifest намеренно не содержит boot image и installer backend. Для другой точной модели копируйте generic template, а не объявляйте поддержанным целое семейство устройств.
